# Stage C: execute, inspect, repair

Use one native Executor and one target at a time. The Executor reads the scientific
contract and current independent review, validates a fresh plan preview, and uses
the Evidence Runtime. If source hashes changed, repair/validate/review and rebind to
existing scope; ask only if the scope itself changes.

For long work use `execute --detach`, retain the returned run ID and inspect
`status --bundle`. Calling execute again on the same bundle observes/reverifies it;
it does not launch another calculation. Keep remote scheduler/run handles in a
declared `run_handle.json` output when using a reviewed remote wrapper. Host names,
paths and scheduler commands come from the user's environment, never this Skill.

Distinguish setup/transport failure, numerical nonconvergence, disagreement with the
paper and figure presentation defects. Inspect raw logs/data before deciding which
one occurred. A failed command or missing output produces no accepted numeric rows.
Failure evidence is valuable even when no normal Bundle can be completed.

Register target results through the controller. A new scientific attempt clears
the selected prior evidence; old files/events remain historical evidence. Reverify
the current Bundle before claiming a result. After a target is terminal, obtain
its independent Critic and target preflight, then the aggregate preflight.

For unrecoverable failure within the current contract/budget, finish a final target
Critic over failure artifacts and a later Supervisor with `BLOCKED: <reason>`.
Create/verify an exhausted-terminal record; this permits a negative summary and
archive, never scientific acceptance. There is no requirement for four fictitious
Critics or four identical failed attempts.

## Presentation-only repair

Copy required immutable numeric outputs into the rendering source as hashed inputs.
Create a plan with `operation_kind: presentation`, `presentation_of` containing the
current numeric Bundle path and manifest hash, the same scientific contract,
execution location/environment and capabilities, and a manual/visual comparison.
The initial grant can cover this reviewed derivative within its resource ceilings.
Bind a fresh independent review; it inherits task scope and does not consume a
scientific attempt. Use `record-presentation` after an independent visual review.
This updates presentation quality without replacing numerical evidence or claims.
